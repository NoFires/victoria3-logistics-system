## Must fix

1. **正式UI数据链丢失逐商品Freight需求贡献**（[logistics_ui.cpp](../../native/src/logistics_ui.cpp)132–138、[native_trade_view.cpp](../../native/src/native_trade_view.cpp)169–177、[logistics_session.cpp](../../native/src/logistics_session.cpp)284–286）
   - **What this is:** 模型已为每个州/市场/商品保存目标、满足、未满足；正式native分支向原版UI发布这些结果。
   - **Problem:** 正式视图只汇总总账，创建商品行时未赋`intermediaryDemand`。现有native用例可得到总账500/500/0，但该商品行的需求贡献按构造逻辑仍为空；旧模型分支的逐商品测试不覆盖实际native分支。
   - **Fix:** 复用已有balances按good聚合并沿正式视图/文档传递，在现有原版显示/提示中可追溯；新增两商品正式分支反例，核对商品合计=作用域总账及过滤不改账。不要从已运输量推算目标需求。
   - **If we skip it:** 能看总量，却不能核对哪些商品造成Freight目标和未满足，MASTER§4.5/A27仍不完成。

2. **部分海路仍没有完整端点或方向**（[native_domestic_model.h](../../native/src/native_domestic_model.h)223–240、[native_trade_geometry.h](../../native/src/native_trade_geometry.h)147）
   - **What this is:** 绘图要将当前原版航运链连接到有证据的港口/海段端点。
   - **Problem:** 当前同档实录仍2条unavailableSea、36条partialSea；前者没有见证端点时无法定向，后者至少一端缺完整接续。代码保留缺几何状态，数值恢复不等于路线完整。
   - **Fix:** 继续追当前原版航运/贸易结果，优先复用已验证入口取得真实接续；逐条核对端点/方向/运河开放关闭及近远景，不硬编码补点或画猜测直线。
   - **If we skip it:** 对应路线缺段/不可绘，不能交付“每笔货流有完整真实路径”。
