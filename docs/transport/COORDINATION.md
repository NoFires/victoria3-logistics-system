# 单写者与分支协调

本文件是并行工作的强制约束。目标：同一时间只有一个活动迁移线；任何第二工作区在开工前必须被看见、被登记，分歧必须在同一分支上用证据裁决，禁止各自推进到交付。

## 1. 当前活动线

| 项 | 值 |
|---|---|
| 正式交付分支 | `worktree-v115-adaptation`（1.15.0 交付） |
| 主工作区 `main` | 归档；除非用户明确提升，不在主工作区继续迁移 |
| 实验分支 | 必须从正式交付分支切出，命名 `exp/<主题>` 或 `trade-getter-port` 这类明确主题；实验分支不得部署、不得改写交付结论 |
| 交付安装 | 只有正式交付分支的构建可以安装；实验 DLL 只做临时快照，测试后恢复安装前状态 |

## 2. 开工前必须做的三件事

1. 运行预检（在仓库任一工作区）：

   ```powershell
   python tools\agent_preflight.py
   ```

   预检要求：当前分支正确、工作区干净、不落后上游、没有其他人的未过期 claim。
2. 登记本次工作（claim 写在共享 `.git` 目录，所有 worktree 可见）：

   ```powershell
   python tools\agent_preflight.py --claim "任务一句话" --owner <会话ID> --round R2xx
   ```

   实验分支额外加 `--allow-branch`；工作区已有本人未提交改动时加 `--allow-dirty`。
3. 确认没有第二个工作区正在做同一主题。`git worktree list` 只用于查看；发现另一工作区有未提交的迁移改动时，**停止开工**，先按第 4 节处理。

收工或交接前：

```powershell
python tools\agent_preflight.py --release --owner <会话ID>
```

claim 默认 8 小时过期；崩溃遗留的 claim 到期后自动失效。不要用 `--force` 绕过他人的有效 claim，除非用户明确授权。

## 3. 提交与轮次

- 每个工作单元结束必须提交；不允许把迁移改动留在工作区跨天。
- 轮次号由 claim 的 `round` 预留；同一时间只能有一个活动轮次。并行实验分支使用 `E-` 前缀，不占用主序列。
- 实验分支合并回正式分支前，必须：完整构建、完整测试、写明与交付基线的差异，并由用户确认。
- 正式分支永远保持可构建、可部署；实验分支不得直接修改 `dist` 后部署。

## 4. 发现分叉时

1. **停止**：不继续写代码、不合并、不部署。
2. **留证**：把另一工作区的源码/测试/文档快照到 `E:\Code\v3-analysis\checkpoints\<日期>-<主题>-divergence`，记录最后修改时间和所在分支。
3. **比对**：以共同基线做三路比对，按文件分类：仅对方改动、仅我方改动、两边相同、两边不同；不要按目录或报告数量判断。
4. **裁决**：按第 5 节证据顺序决定唯一实现；能取长补短时，只移植有独立证据且能通过本分支测试的最小功能，不整包覆盖。
5. **记录**：在 `docs/transport/DECISIONS.md` 记下裁决、被拒方案和恢复入口；在 `AGENTS.md` 第 6 节记一轮日志。

## 5. 分歧的证据顺序

从强到弱：

1. 当前 1.15.0 构建的实机行为（DLL 已加载、正式 UI/数据）；
2. 完整统一入口通过 + 同一构建的部署/生命周期/性能证据；
3. 官方等价 harness（与交付二进制、环境、判据一致）；
4. 隔离的原始机器码/合成世界 harness；
5. 静态反汇编/RTTI/偏移推导。

低层证据不能推翻高层实机证据；未实载的代码不能覆盖已交付且通过实机验收的实现。双方各有优势时，按功能拆分移植：例如“取对方的选择器 ABI + 保留我方的表语义”，而不是二选一。

## 6. 反例（本文件的由来）

2026-11-06 发现主工作区与 `worktree-v115-adaptation` 各自维护了一套 R195–R202/R200–R219 迁移记录：31 个文件相同、11 个仅对方改动、4 个仅我方改动、36 个两边不同，轮次号重叠但内容不同，且主工作区改动长时间未提交。后续必须用 claim + 预检避免同类并行；发现后按第 4、5 节处理，不能直接合并两套 R 号或两套候选哈希。
